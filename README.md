## Project Reflection

The Gaming Room was the client for this project, and they wanted to expand their existing Android game, *Draw It or Lose It*, into a web-based application that could support multiple platforms. The software needed to allow multiple games, teams, and players while making sure that names remained unique and only one instance of the game service existed at a time. One thing I did particularly well while developing the software design document was analyzing the different operating platforms and considering their strengths, weaknesses, and requirements before making a recommendation. This helped me understand that choosing a platform should be based on the needs of the application rather than simply choosing the operating system I am most familiar with.

Working through the design document was helpful because it gave me a plan to follow before focusing completely on the code. Breaking the application down into its requirements, constraints, architecture, and individual components made it easier to understand how everything needed to work together. If I could revise one part of my work, I would improve the level of detail in some of my technical recommendations. I would provide more explanation about why certain technologies or architectural decisions were selected and compare more possible alternatives before making a final recommendation.

When interpreting the user's needs, I focused on requirements such as supporting multiple platforms, allowing multiple users to participate, maintaining unique game and team names, and creating an application that could grow as more users joined. Considering the user's needs is important because software can function correctly from a technical perspective and still fail if it does not solve the user's actual problem or provide a good experience. My approach to designing the software was to first understand the requirements and then break the system into smaller components that could be designed and implemented individually. In the future, I would continue using techniques such as reviewing requirements, creating UML diagrams, identifying design constraints, comparing platform options, and considering security and scalability early in the development process. This project showed me that spending more time planning and documenting a system before development can make the actual implementation more organized and easier to manage.
